# Architecture Decision Records

ADR фиксируют контекст, принятое решение и его последствия. Они объясняют причины
архитектуры, но не заменяют актуальные инструкции и runbooks.

| ADR                                           | Решение                                           | Статус  |
| --------------------------------------------- | ------------------------------------------------- | ------- |
| [0001](0001-modular-monolith-with-workers.md) | modular monolith + workers                        | принято |
| [0002](0002-api-protocols.md)                 | GraphQL для бизнес-данных, REST для upload/health | принято |
| [0003](0003-asynchronous-processing.md)       | RabbitMQ для фоновой обработки                    | принято |
| [0004](0004-environments-and-delivery.md)     | окружения и delivery flow                         | принято |

Если решение меняется существенно, создаётся новый ADR со ссылкой на предыдущий и
статус старого меняется на `заменено`. Нельзя переписывать исторический контекст так,
будто новое решение существовало изначально.
